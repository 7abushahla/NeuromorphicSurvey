# A11 — Mixed-Timestep / Per-Layer-Timestep SNN Audit

Audit of quantization-aware conversion, mixed-precision, and mixed-timestep SNN methods, focused on hardware evidence and the execution model each paper assumes for a per-layer (heterogeneous) timestep horizon. Compiled 2026-09-15.

---

## 1. PASCAL (arXiv:2505.01730, TMLR 2025)

**Full title:** "PASCAL: Precise and Efficient ANN-SNN Conversion using Spike Accumulation and Adaptive Layerwise Activation." Pranav Ramesh, Gopalakrishnan Srinivasan (IIT Madras). Published in *Transactions on Machine Learning Research* (12/2025). OpenReview: https://openreview.net/forum?id=kIdB7Xp1Iv. arXiv v2 (11 Dec 2025): https://arxiv.org/abs/2505.01730. PDF: https://arxiv.org/pdf/2505.01730.

### What the method does

PASCAL has two components:
1. **PASC (Precise ANN-SNN Conversion)** — a spike-accumulation IF formulation, proved mathematically equivalent to an ANN with QCFS activation, that achieves near-zero conversion error at any uniform T. Uses excitatory *and* inhibitory (negative) spikes and a three-stage integrate procedure per layer (Algorithm 1/2) to handle transitions between layers whose previous/current quantization steps (L_{n-1}, L_n) differ.
2. **AL (Adaptive Layerwise) activation** — a statistical layer-sensitivity metric (Van Der Eijk's Agreement × (skewness²+1) × kurtosis, computed on the QCFS activation histogram) used to assign a *different* quantization step L (hence a different unrolled timestep count T_l) to each layer, then retrain. This is the mixed-timestep component.

### T_eff and how it is computed

PASCAL reports **T_eff ≈ 3.14** for ResNet-18 on CIFAR-10 (95.34% accuracy), among other configurations (VGG-16/CIFAR-10: 2.13; VGG-16/CIFAR-100: 4.54; VGG-16/ImageNet: 9.92–12.40; ResNet-34/ImageNet: 12.94).

The exact formula (Eq. 16, Section 4.3):

> T_eff = (1/|L_tot|) · Σ_l  r_l^E · T_l

where L_tot is the total number of layers, T_l is the number of timesteps of the "vanilla" (uniform-T) SNN for the corresponding layer, and r_l^E is a per-layer weighting factor (the extracted text does not spell out r_l^E in full LaTeX; contextually it is a relative-operation/energy weight per layer, consistent with the paper's later "layerwise count of operations" appendices A.5–A.7). **This is explicitly a (weighted) arithmetic MEAN over layers, normalized by 1/|L_tot|** — not a sum, and not a measured execution latency. Table 4, where T_eff first appears, is titled "SNN accuracy and effective timesteps" and lists the per-layer L assignment (e.g. ResNet-18: `[4,4,4,1,4,4,4,1,4,1,1,1,1,1,1,1,4]`) alongside the single scalar T_eff = 3.14 computed from it.

### Execution model assumed

The PASC three-stage algorithm (Section 3.2) explicitly describes **sequential, layer-by-layer temporal execution**: for a generic layer with previous step L_{n-1} and current step L_n, stage 1 runs L_{n-1} timesteps, stage 2 runs max(L_{n-1}, L_n) − 1 timesteps, stage 3 runs L_n timesteps, and "the output spike train generated by the PASC algorithm is effectively unrolled across L_n timesteps by the subsequent layer... after each layer, the number of inference timesteps is equal to the value of the quantization step, i.e. T = L_n." This describes a per-layer temporal contract but the paper does not explicitly state whether the *total* network latency under this scheme is the sum of per-layer horizons (sequential dataflow accelerator) or something smaller (a pipelined multi-core scheme). No formula for total/cumulative network latency under heterogeneous per-layer T is given anywhere in the main text.

### Critical finding — hardware evaluation does not cover the mixed-timestep (AL) mode

**Every hardware number in Appendix A.10 is reported at a fixed T=4** ("Default IF (T=4)" vs "PASC IF (T=4)"), i.e. for the *uniform*-timestep PASC formulation, not for the Adaptive Layerwise (AL) mixed-timestep configuration that produces the headline T_eff = 3.14 result (Table 4/5, marked "PASCAL (T_eff)" as distinct from "PASC (T_norm)"). The RTL synthesis + cycle-accurate simulator validates only that the PASC IF neuron itself (excitatory + inhibitory spike-count logic) adds negligible overhead relative to a standard IF neuron, under a single global T shared by all layers. **The paper never synthesizes, simulates, or measures the mixed-timestep AL execution model on any accelerator.** The temporal-mismatch problem this would create between successive layers of unequal L_l (the same problem QAC's Section 4.3 calls "Temporal Alignment" and later cites as a source of pipeline stalling — see §2 below) is not addressed on hardware at all in PASCAL; it exists only in the software/PyTorch simulation used to produce Tables 4–6.

### Classification: **E4 for the PASC-IF-overhead claim at uniform T (RTL synthesis on 40nm + cycle-accurate simulator, LoAS/SparTen-based); E5 (software/PyTorch simulation only) for the mixed-timestep T_eff=3.14 headline result.** No hardware evidence of any kind exists for the mixed-timestep AL mode specifically.

**Scope caveat on the E4 claim:** PASCAL's own A.10 validation is narrow — a single model (VGG-16), single dataset (CIFAR-10), single uniform timestep (T=4), and a single design point. It is a one-off overhead check ("does the PASC-IF neuron cost more than a standard IF neuron"), not a systematic design-space accelerator study.

### Related follow-on accelerator papers (found during cross-check; genuinely relevant to a neuromorphic-hardware survey)

Two newer, closely related accelerator papers were surfaced while verifying the claim above. Both build on the same LoAS/SparTen baselines PASCAL uses, with near-identical RTL synthesis methodology, and are worth citing alongside PASCAL for anyone assembling hardware evidence in this space — but neither is a mixed-timestep (per-layer-T) paper; both use uniform per-layer T.

- **APEX** — "APEX: A Dual-Sparsity Accelerator for Precise and Efficient SNN Inference," arXiv:2608.19046 (19 Aug 2026). Author list includes Gopalakrishnan Srinivasan (a PASCAL co-author), per the alphaXiv listing: https://www.alphaxiv.org/abs/2608.19046. APEX integrates the PASC-IF neuron natively into the LoAS dataflow as a fully combinational 3-cycle datapath, synthesized with Synopsys Design Compiler at **400 MHz** (not 560 MHz — a different clock target from PASCAL's own A.10 run) on **40 nm CMOS**, and sweeps T ∈ {4, 8, 16} with mixed INT4/INT8 precision across AlexNet, VGG-16, and ResNet-18/34 — i.e., a much broader design-space sweep than PASCAL's single-point A.10 check. APEX's introduction states "the hardware implications of deploying the PASC-IF neuron remain unexplored" and "no existing SNN accelerator supports the PASC-IF neuron" — language that reads as if PASCAL's own A.10 synthesis did not exist. This is either (a) promotional overstatement common when a follow-on hardware paper motivates its own novelty, or (b) a fair characterization given how narrow PASCAL's single-configuration check actually is relative to APEX's full design-space study and *native* (not bolted-on) PASC-IF datapath. Either reading is consistent with PASCAL's A.10 being real but limited — it does not support reclassifying PASCAL's A.10 as absent.
- **NeuroFlex** — "NeuroFlex: Column-Exact ANN-SNN Co-Execution Accelerator with Cost-Guided Scheduling," arXiv:2511.05215 (7 Nov 2025; a later, retitled variant "Lossless Element-Level ANN-SNN Co-Execution for Efficient Sparse Inference" appears at arXiv:2609.14092, 12 Sept 2026). NeuroFlex is a hybrid ANN/SNN accelerator with LoAS (SNN) and SparTen (ANN) as baselines, "replace[s] the activations in LoAS and Prosperity with PASCAL's spiking activation," and states: "We implement key components of NeuroFlex and all baselines in RTL and synthesize with Synopsys Design Compiler at **560 MHz** in **40 nm** technology node" — this is the paper whose parameters (560 MHz, 40nm, LoAS+SparTen baselines) most closely match what PASCAL's own A.10 reports, which is the most plausible source of the cross-attribution concern that triggered this re-check. NeuroFlex is a column-level ANN/SNN co-execution scheduler, not a mixed-timestep (per-layer-T) method.

Both APEX and NeuroFlex postdate PASCAL's TMLR publication (Dec 2025) and were not part of the original audit scope; they are recorded here as adjacent hardware evidence for the broader survey, not as evidence for or against the mixed-timestep claims in §1–3 of this document.

## 2. QAC — "QAC: Quantization-Aware Conversion for Mixed-Timestep Spiking Neural Networks"

**Authors:** Mingxin Guo, Qianpeng Li, Yaoyao Li, Jian Cheng, Liang Chen. Submitted to **ICLR 2025** (submission #8774). OpenReview: https://openreview.net/forum?id=D4sQzdMvcG (first submitted 27 Sept 2024, last modified 5 Feb 2025). Full PDF used for this audit: https://openreview.net/pdf/c632e28e91b259f386f9fc22d7821fcd868acf1f.pdf. As of this audit the forum still shows "Submitted to ICLR 2025" without an acceptance venue label; **NOT FOUND** — no confirmation was located of final accept/reject decision or of a later publication venue for QAC under this title. (Reviewer-level comments/scores could not be retrieved — OpenReview's forum and API endpoints returned a CAPTCHA/challenge wall to all automated fetch tools used, including a headless-browser attempt that failed because the Chrome extension was not connected in this environment. Only the paper PDF itself, which is separately cached/indexed, was accessible.)

### What the method does

QAC proves a "Theorem 1": the timesteps T of an SNN with soft-reset IF neurons are mathematically equivalent to the quantization level 2^n of a matched-precision quantized ANN activation. It then trains ANNs with **mixed-precision quantization** (different bit-width n_l per layer, via one of four parameterizations of the LSQ-style quantizer) and converts the result into an SNN with **mixed timesteps {T_1, T_2, ..., T_l}**, one per layer. It also introduces a "Temporal Alignment" step (temporal averaging expansion) to reconcile the differing temporal dimensions between adjacent layers, and a calibration scheme for the initial membrane potential/threshold.

### T_eff reported

Confirmed: **ResNet-18 on CIFAR-10 achieves 95.29% top-1 accuracy with an average of 2.76 timesteps** (quoted directly from the paper). Other reported figures: VGG-16/CIFAR-10 = 2.33 timesteps (94.78%); ResNet-20/CIFAR-10 = 3.74 timesteps (91.13%); VGG-16/ImageNet = 3.47 timesteps (66.38%). All of these numbers are computed from the "Case 4: (t, α)" parameterization, described in the paper as offering "the fewest timesteps while maintaining accuracy close to the original ANN."

### How T_eff is computed

Section 5.1 states explicitly that Figure 11 shows "the **average** quantization bit-width and corresponding timesteps for all layers... under four different quantization parameter schemes," and that the reported T values throughout the results tables are this **per-layer average** ("our method uses mixed-timesteps and has converged to nearly optimal timesteps"). No sum, weighted latency, or cycle count is used anywhere for the headline T numbers — **it is a simple/derived mean across layers of the network**, exactly the same pattern as PASCAL's T_eff.

The paper itself flags the latency risk of the naive alternative: Section 4.2 states, "attempting to enhance accuracy by uniformly increasing timesteps across layers can lead to substantial inference delays on the order of **O(NT)**, where N is the number of layers and T is the timestep count" — i.e. QAC's own motivating argument for going to mixed-timestep in the first place is that a uniform-T SNN's true cost scales with N×T (layers × timesteps), which is a sum/product over layers, not a mean. Having made this point to motivate the method, the paper then reports the *mixed*-timestep result as a mean, without reconciling the two.

### Appendix statement on pipeline stalling — Section 7.7 "Hardware Efficiency Analysis"

This is the exact passage (quoted verbatim from the OpenReview-cached PDF, Section 7.7, p. 22 of the appendix):

> "Using QAC to build mixed timestep SNNs allows them to run on SNN hardware while preserving the asynchronous nature of SNNs. SNN hardware has two mainstream implementation approaches: ANN accelerator variants and non-Von Neumann distributed multi-core architectures (e.g., TrueNorth Akopyan et al. (2015), Loihi Davies et al. (2018))... ANN accelerator variants primarily achieve asynchronous computation by sending non-zero inputs to processing element PE arrays and performing spike-based matrix calculations. These accelerators only compute one part of the neural network at a time, iterating to cover the entire network. Algorithm 2 [Li et al. (2024b)] shows the data flow, where the timestep for each layer is T. For mixed-timestep SNNs, we modify the timestep T_l for each layer and average the outputs of each layer along the time dimension. These two operations do not change the original data flow, allowing the model to run on this type of hardware. **In contrast, multi-core neuromorphic hardware deploys the neurons of all layers across different cores. When neurons receive spike events, they immediately perform spike-based computations, achieving asynchronous execution. The network runs on hardware in a pipelined manner.** As shown in Figure 4 [Zhong et al. (2024)], at time T1, Layer 1 processes the data from Sample 1. At T2, Layer 2 processes the data from Sample 1 (i.e., the output of Layer 1 at T1), while Layer 1 processes the data from Sample 2. **For mixed timestep SNNs, a time alignment strategy must be used to handle the different timesteps of each layer. During pipeline execution, Layer 2 must wait until Layer 1 completes T_l1 timesteps before it can start computation. Although mixed timestep SNNs can run on this type of hardware, pipeline stalling may occur, introducing computational delays and preventing the hardware from achieving optimal performance.**"

This is a direct, explicit acknowledgment by the authors that under a pipelined multi-core execution model (the standard model for neuromorphic chips like TrueNorth/Loihi), mixed-timestep SNNs cause **pipeline stalling** — the exact failure mode hypothesized in the audit brief. No quantitative estimate of the resulting stall penalty (in cycles, latency, or throughput loss) is given anywhere in the paper; the statement is qualitative only.

### Hardware evaluation quality

No RTL synthesis, no cycle-accurate simulator, no technology node, and no accelerator implementation of any kind is reported for QAC. Section 7.7 is a **purely descriptive/qualitative discussion** referencing prior accelerator architectures (LoAS/Li et al. 2024b's dataflow "Algorithm 2," TrueNorth, Loihi, a pipelining figure from Zhong et al. 2024) without running, synthesizing, or simulating anything. Section 7.8 ("Energy Comparison") computes analytical energy estimates for INT8 MAC vs. addition-only SNN operations using published per-operation energy figures from Horowitz (2014) and Potipireddi & Asati (2013) — an **analytical back-of-envelope model**, not a synthesized or simulated hardware run.

### Classification: **E3 (documented execution path, explicitly including its own failure mode — pipeline stalling — but no run performed) for the hardware/execution-model discussion; E5 (software simulation only) for all accuracy/T_eff results.** No E1/E2/E4 evidence exists anywhere in the paper.

## 3. MT-SNN (Guo et al., ICLR 2026 submission — WITHDRAWN)

**Full title:** "Mixed-Timestep Spiking Neural Networks with Temporal Alignment for Ultra-Low Latency Conversion." Authors: **Mingxin Guo, Qianpeng Li, Xingting Yao, Jian Cheng, Liang Chen** (same first author and largely overlapping author list as QAC — this is the direct successor/expansion of QAC). Submitted to **ICLR 2026**, 19 Sept 2025 (modified 08 Jan 2026). OpenReview: https://openreview.net/forum?id=4dwAZRr9L5. Status: **"ICLR 2026 Conference Withdrawn Submission."**

### What the method claims

Confirmed as the mixed-timestep SNN successor to QAC: each layer operates with "an optimally selected time-step," jointly optimizing quantization levels and firing thresholds, plus a "temporal alignment scheme" addressing "a temporal dimension mismatch issue in MT-SNNs." Headline result: **ResNet-34 on ImageNet-1K, 73.63% top-1 accuracy at 4.88 average timesteps.**

### Withdrawal reason and reviewer objections

Only the top-level metadata (title, authors, abstract, TL;DR, submission/withdrawal dates, "Withdrawn Submission" status) was retrievable. **The specific reviewer objection(s) that led to withdrawal, and any reviewer scores, could not be confirmed or quoted.**

What can be established from public metadata:
- The paper was submitted 19 Sept 2025 and the forum's "modified" date (which for a withdrawal typically reflects the withdrawal notice) is 08 Jan 2026 — consistent with a withdrawal occurring near or after the ICLR 2026 review/rebuttal period rather than immediately after submission, suggesting the authors withdrew after seeing reviews rather than pre-emptively.
- The same author group (Guo, Yao, Li, Li, Cheng, Chen) subsequently published essentially the same work — same core claim (73.63% top-1 ImageNet-1K accuracy at 4.88 average timesteps), same "temporal alignment" framing, but now branded as **"Scaled Synaptic Current Accumulation (SSCA)"** replacing the earlier "temporal averaging expansion" — in **Frontiers in Neuroscience**, 2026: "Mixed-Timestep Spiking Neural Networks: A Temporal Alignment Framework for High-Efficiency Neuromorphic Computing," published 2026-08-12: https://www.frontiersin.org/journals/neuroscience/articles/10.3389/fnins.2026.1783326/full. This strongly suggests the ICLR 2026 withdrawal was a strategic withdraw-and-resubmit-elsewhere move rather than an abandonment of the work, and that the underlying temporal-mismatch problem (which QAC's own appendix already flags as causing pipeline stalling — see §2) required a revised technical fix (SSCA) before the paper found a venue. Whether SSCA actually resolves the pipeline-stalling problem on real pipelined multi-core hardware, or merely resolves the *numerical* temporal-dimension mismatch in software simulation, is **NOT FOUND** — the abstract describes SSCA as something that "aligns inter-layer propagation in the synaptic-current domain **without instantiating a standalone temporal-alignment kernel**," which reads as a software/simulation-level fix (avoiding an extra kernel in the simulated forward pass) rather than a hardware-validated fix for pipeline stalling.

### Hardware evaluation

**NOT FOUND.** Neither the ICLR 2026 withdrawn abstract nor the Frontiers abstract mentions any accelerator implementation, RTL synthesis, cycle-accurate simulator, or physical neuromorphic chip. Both describe experiments on CIFAR-10, ImageNet-1K, CIFAR10-DVS, and DVS-Gesture — standard software/GPU benchmarking datasets, with no stated hardware target.

### Classification: **E5 (software simulation only)** based on available abstracts; no hardware evaluation of any kind found in either the withdrawn ICLR version or the Frontiers republication.

## 4. Other mixed-timestep / per-layer-T / heterogeneous-timestep SNN work found

### 4.1 "Timesteps meet Bits: Low-Latency, Accurate, & Energy-Efficient Spiking Neural Networks with ANN-to-SNN Conversion" (OpenReview: https://openreview.net/forum?id=KjiNHPinrS)
Modifies the SNN IF neuron and shifts BN bias terms per layer to reduce timesteps exponentially; reports 73.30% ImageNet accuracy at T=4 (uniform, not mixed-timestep in the per-layer sense). Adds an ℓ1 sparsity regularizer for spike-count reduction. This is a low-latency uniform-T conversion method, not a per-layer mixed-timestep method; included here only because it was surfaced by the search and is adjacent/relevant to the low-latency-conversion literature this audit is mapping.

### 4.2 "One-Timestep is Enough: Achieving High-performance ANN-to-SNN Conversion via Scale-and-Fire Neurons" (ICLR 2026 submission: https://openreview.net/forum?id=O3CuUy5XAX)
Proposes "Temporal-to-Spatial Equivalence Theory": multi-timestep IF neurons can be replaced by single-timestep **multi-threshold neurons (MTN)**, i.e. it collapses the temporal dimension into multiple simultaneous thresholds at T=1 rather than spreading precision across layer-varying T. This is the inverse direction from mixed-timestep (it eliminates timesteps altogether via multi-threshold spatial encoding) but is directly relevant background: it demonstrates that the "timesteps ≈ bit-width" equivalence QAC/PASCAL/MT-SNN rely on can also be cashed out spatially (multiple thresholds in one timestep) instead of temporally (multiple timesteps), which sidesteps the pipeline-stalling problem entirely since there is only ever one global T=1. No hardware evaluation found in the abstract; reports 88.8% top-1 ImageNet-1K at T=1, which is a software/simulation result.

### 4.3 "MT-SNN: Enhance Spiking Neural Network with Multiple Thresholds" (Wang & Zhang, arXiv:2303.11127)
**Name collision warning:** this is a *different* "MT-SNN" from the Guo et al. withdrawn ICLR 2026 paper in §3 above — "MT" here stands for "Multiple Threshold," not "Mixed-Timestep." It proposes PARALLEL and CASCADE multi-threshold neuron variants (again, a spatial multi-threshold-per-timestep approach, similar in spirit to §4.2) to recover precision lost to binarization, evaluated on TPU (TensorFlow implementation), not on neuromorphic silicon. Included here to flag the naming collision for anyone searching "MT-SNN," not because it is a per-layer mixed-timestep method.

### 4.4 "Temporal Flexibility in Spiking Neural Networks: Towards Generalization Across Time Steps and Deployment Friendliness" (Du, Wu, Deng, Gu; ICLR 2025 **Poster** — accepted, unlike QAC/MT-SNN above). arXiv: https://arxiv.org/html/2503.17394v1. Code: https://github.com/brain-intelligence-lab/temporal_flexibility_in_SNN

This is the most hardware-credible related work found in this audit, though it addresses a **related but distinct problem** from per-layer heterogeneous T:

- **What it does:** "Mixed Time-step Training" (MTT) partitions an SNN into stages; during each training iteration, each stage is *randomly* assigned a different timestep (drawn from {1,...,6}), with spikes communicated between stages via learned "communication modules." The goal is **temporal flexibility/generalization** — a single trained model that performs well whether evaluated at T=1, T=2, ..., T=20, or on a fully event-driven (T-free) chip — not a single forward pass with simultaneously heterogeneous per-layer T. This is an important distinction: MTT produces a model **compatible with many different single global T values, and with T-free async hardware**, rather than a model that must run with T_1 ≠ T_2 ≠ ... ≠ T_L within one inference.
- **Hardware evaluation — genuinely physical silicon (E1/E2):** "We first train two networks on NMNIST using SDT and MTT respectively, and then **deploy them directly on Speck2e Devkit** (Richter et al., 2023)." They report a spike-difference (SD) metric between their own software simulator and actual on-chip output: **3.92% SD** on NMNIST (vs. 2.81% SD between two identical on-chip runs — i.e., close to hardware-reproducibility noise floor — and vs. 28.77% SD between a conventional time-stepped simulation and the actual on-chip output, which they use to argue conventional time-stepped training/simulation does *not* faithfully predict real event-driven chip behavior). This is a genuine physical-silicon deployment and measurement (Speck2e — a commercial fully event-driven asynchronous neuromorphic chip, SynSense), making this **the only paper in this audit with confirmed physical hardware measurement (E1/E2)** — but critically, the Speck2e chip is **fully event-driven / asynchronous with no discrete timestep concept at all**, so this deployment sidesteps rather than solves the "different layers need different discrete T" problem: on Speck2e there is no T to be heterogeneous *about*. The paper's own framing supports this reading — it calls conventional discrete-T SNNs "temporally inflexible" specifically because they cannot run on "time-step-free fully event-driven chips," and MTT's contribution is making a network's *weights* transferable across that boundary, not executing a mixed-integer-T schedule on synchronous hardware.
- **Classification: E1/E2 (physical Speck2e silicon, accuracy/spike-difference measured) for the event-driven deployment claim; but this does not constitute hardware evidence for the QAC/PASCAL/MT-SNN style of per-layer heterogeneous discrete-T mixed-timestep execution**, which is a different problem (synchronous/clocked hardware where different cores/layers would need to advance different numbers of discrete ticks).

### 4.5 Mixed-precision quantization → per-layer bit-width → timestep mapping, generally
Both PASCAL (AL activation, §1) and QAC/MT-SNN (mixed-precision quantized ANN → mixed-timestep SNN, §2–3) are themselves instances of "assign different bit-widths per layer, then map bit-width to timestep count via the QCFS/soft-reset equivalence theorem." No additional papers doing this *specific* bit-width→timestep mapping beyond PASCAL, QAC, and MT-SNN were found in this search pass. General (non-SNN) mixed-precision quantization background cited inside QAC's own related-work section includes HAQ (Wang et al., 2019, RL-based bit-width allocation), HMQ (Habi et al., 2020, "Hardware friendly Mixed precision Quantization block"), and DNAS (Wu et al., 2018, differentiable bit-width search) — these are ANN-only mixed-precision methods, included here only as the lineage QAC explicitly draws its mixed-precision-quantization machinery from.

## 5. Dynamic / early-exit timestep methods (distinct from per-layer T) — and their hardware claims

These stop inference **early in time for the whole network, per input sample** (a single global T that varies sample-to-sample, decided at runtime by a confidence/policy mechanism), as opposed to different **layers** within one sample using different, fixed T. They are conceptually and architecturally distinct from the QAC/PASCAL/MT-SNN "per-layer T" family, but the audit brief asked for them to be covered and hardware-audited.

### 5.1 SEENN (Li, Geller, Kim, Panda; NeurIPS 2023). arXiv: https://arxiv.org/abs/2304.01230
- **What it does:** SEENN-I uses confidence-score thresholding to exit early (per sample); SEENN-II uses a reinforcement-learned policy network (ResNet-8, 0.547% the compute of ResNet-19) to decide when to exit. Reports 96.1% CIFAR-10 accuracy at an average of 1.08 timesteps (SEENN-II); on ImageNet, ~1.1 average timesteps to match a 6-timestep model's accuracy.
- **Hardware evaluation:** Section 4.3 "Hardware Efficiency" states explicitly: "Due to the sequential processing nature of SNNs, the latency is generally proportional to T on most hardware devices. Therefore, **we directly use a GPU (NVIDIA Tesla V100) to evaluate the latency** (or throughput) of SEENN." Energy is estimated with a standard per-operation cost table (not a synthesized/simulated accelerator model), citing prior work's convention. **This is GPU throughput measurement, not neuromorphic hardware** — classification **E5**.
- **One partial exception:** the paper's appendix (per an OpenReview-hosted copy, https://openreview.net/attachment?id=Xgo7AiNZVt) includes a conceptual cycle-by-cycle diagram of a **pipelined implementation for multiple concurrent input samples** ("Cycle 1: Input1(T=1,layer=1)"; "Cycle 2: Input2(T=1,layer=1), Input1(T=1,layer=2)"; etc.), sketching how a systolic/pipelined multi-core accelerator could overlap different samples' early-exit computations across layers and cycles. This is a **design sketch/diagram only** — no synthesis, no simulator, no cycle-accurate model backs it. Classification for this piece: **E3** (documented path, no run).

### 5.2 Dynamic Confidence (Li, Jones, Furber; ICCV 2023). https://openaccess.thecvf.com/content/ICCV2023/papers/Li_Unleashing_the_Potential_of_Spiking_Neural_Networks_with_Dynamic_Confidence_ICCV_2023_paper.pdf
- **What it does:** Decodes a confidence signal from SNN outputs over time and uses a Pareto-front-calibrated threshold to decide per-sample when to terminate inference early. Reports (with QFFS) 94.11% CIFAR-10 accuracy at 2.52 average timesteps and 72.52% ImageNet accuracy at 2.86 average timesteps; with QCFS (no negative spikes, more hardware-compatible), 73.30% ImageNet accuracy at 49.54 average timesteps (vs. 72.85%/64 timesteps for the non-dynamic baseline — i.e. only a modest ~23% latency reduction in the QCFS, no-negative-spike setting, versus a much larger reduction claimed for the negative-spike QFFS setting).
- **Hardware evaluation — explicit self-reported limitation, directly on point for this audit:** "Similar to other SNN algorithm research, our proposed method is demonstrated and evaluated through the **simulations on GPUs, the real power saving when running on neuromorphic hardware is unknown to us**. Given that neuromorphic hardware's energy consumption is dominated by the multicast routing of spikes, we report the data on the **spike count reductions** achieved by our method [as a proxy]." This is a direct authorial acknowledgment that no real hardware validation was done, and that even the proxy metric (spike count) is only indirectly connected to actual neuromorphic power. Classification: **E5**, with the paper's own text confirming the E5 boundary explicitly.
- The paper also separately notes that not all neuromorphic hardware supports the negative spikes their best (QFFS) results depend on — a hardware-compatibility caveat on top of the missing hardware validation.

### 5.3 Distinction the audit brief asked to record
Both early-exit families (SEENN, Dynamic Confidence) reduce the effective *T* by adapting how many timesteps are run for the network **as a whole**, per input; they do not require any layer to run for a different number of timesteps than any other layer *within* a given inference. This means they **do not** inherit the pipeline-stalling problem QAC's Section 7.7 describes for genuinely heterogeneous per-layer T (§2 above) — a pipelined multi-core neuromorphic accelerator can, in principle, run an early-exit network with a uniform per-layer T that is simply cut short in the temporal (not spatial/layer) dimension once confidence is reached, without layers needing to wait on each other for *different* numbers of ticks. Neither paper makes this argument explicitly, but it follows from their own architecture descriptions (single global T decision point, not per-layer T assignment).

## 6. Can any simulator or neuromorphic chip execute a genuinely per-layer heterogeneous timestep horizon in a single forward pass?

**Finding: no — confirmed by direct citation, not merely assumed.**

The clearest citable evidence found is **NeuroScale** (Nature Communications, 24 Nov 2025): "A deterministic neuromorphic architecture with scalable time synchronization." https://www.nature.com/articles/s41467-025-65268-z. This paper's entire motivation is that essentially all existing large-scale neuromorphic chips advance time via a **single global synchronization signal shared by every core**:

> "An alternate approach is to model time explicitly. In the standard realization of this approach, the neuromorphic system includes a mechanism to synchronize the operations of all neurons and synapses. **The TrueNorth system uses an externally controlled signal that is distributed to all the hardware components of the architecture. This signal, typically operating with a frequency of 1 kHz, is used to advance time for all components of the system.** The C2 large-scale cortical software simulator implemented on the Blue Gene/P architecture uses barrier synchronization to advance time... **Intel's Loihi and Loihi 2 architectures also implement barrier synchronization to advance time. Tianjic uses a global clock for all its coordination processes, including advancing time.**"

This directly confirms, for the four most-cited large-scale digital neuromorphic platforms (TrueNorth, Loihi, Loihi 2, Tianjic), that every core/layer advances the same discrete time index in lockstep via a global barrier or global clock signal — there is architecturally no notion of "layer 3 is at tick 8 while layer 4 is still at tick 2" on these chips; a global barrier prevents any core from proceeding to tick t+1 until all cores have finished tick t. This is precisely the mechanism that would produce QAC's "pipeline stalling" if a mixed-timestep SNN (with per-layer T_l) were mapped onto this kind of hardware: the barrier-synchronized advance forces every layer to wait for the slowest (highest-T_l) layer at each synchronization point, or equivalently the software abstraction of "layer l runs for T_l ticks" has no native hardware primitive — the hardware only knows how to advance one global tick for everyone.

NeuroScale's own contribution (a decentralized, locally-and-aperiodically-synchronized architecture) is explicitly framed as breaking with this global-barrier norm to solve a *different* scaling problem (system size / wire congestion), not to support mixed-timestep SNN inference — mixed-timestep execution is not mentioned in the abstract or the portion of the paper retrieved, and **NOT FOUND**: no evidence that NeuroScale's decentralized synchronization has been proposed or evaluated as a solution to the per-layer mixed-timestep pipeline-stalling problem specifically.

On the **software/GPU-simulator side**, no paper in this audit reports a simulator capable of executing per-layer heterogeneous T within a single forward pass either — QAC and PASCAL's own T_eff numbers are computed by running each layer at its own T_l as a **separate, layer-local unrolling** inside a standard PyTorch/SpikingJelly-style simulation loop, then *time-aligning* the resulting spike trains between layers via an explicit "temporal alignment" / "temporal averaging expansion" module (QAC §4.3; PASCAL implicitly via its three-stage PASC algorithm) before the next layer can consume them. This confirms that even in **software**, there is no native mechanism for a layer at T_l to hand its output directly to a layer at T_{l+1} timesteps without an explicit re-alignment operation bridging the two; the standard simulator abstraction (a single `for t in range(T)` loop advancing the whole network together, as used by frameworks such as SpikingJelly's multi-step mode) has to be worked around, not natively supported, to realize mixed-timestep execution even outside of real hardware.

**Conclusion for this section:** confirmed, not merely assumed — both real neuromorphic silicon (TrueNorth/Loihi/Loihi2/Tianjic, per NeuroScale/Nature Comms 2025) and the standard software simulation abstraction require an explicit global-tick or explicit-realignment workaround to represent per-layer heterogeneous T; none of the three target papers (PASCAL, QAC, MT-SNN) demonstrate a simulator or chip that executes such a horizon natively in one forward pass, and QAC's own appendix explicitly predicts the pipeline-stalling consequence of trying to force this onto real pipelined hardware.
